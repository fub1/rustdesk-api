# 官方 1.5.0 管理员 CLI：已支持范围

PRE01-B / DEV02 首批实现 `POST /api/devices/cli`，PRE02-B增加地址簿条目分配，PRE02-D增加命名策略关联，采用已确认的管理员 CLI 准入。客户端基线为官方 1.5.0 `fada664df7a294d1d1a9ca3e7cd3637069122f17`，发送链在 `src/core_main.rs:542–645`。

## 凭据、目标与响应

请求必须使用有效本地管理员会话：`Authorization: Bearer <token>`。没有新增专用操作 token 表；普通用户、失效会话不能分配。事务内重查用户启用、管理员角色、唯一会话、数据库期限及 middleware 已验证的有效截止时间，不能只信任先前的角色快照。

`id`、`uuid` 均为非空字符串，必须与同一条已登记设备逐字节匹配。它们是资源选择条件，管理员 Bearer 才是授权依据；这不证明发件者就是该设备。未知设备不能由此创建。

成功只在提交后返回 HTTP 200 **空文本**，对应官方 CLI 的 Done 判断。所有失败返回非空 `{"error":"..."}`，不能让不支持或未完成的动作显示 Done。匿名 sysinfo 不是此操作的授权替代入口。

## 本批字段

除 id/uuid 外至少提供一项支持字段。所有值只能是字符串；未知字段、重复键、null、错误类型和尾随 JSON 整请求拒绝。

| 字段 | 实际效果 | 缺失 / 空串 |
| --- | --- | --- |
| user_name | 在当前启用用户中按精确用户名唯一匹配，修改设备 user_id | 缺失保留；空串拒绝，不默认到 owner1 |
| device_group_name | 在设备组字典按精确名称唯一匹配，修改设备 group_id | 缺失保留；空串或歧义拒绝；设备组与用户共享组不同 |
| device_name | 修改设备 hostname | 缺失保留；空串清除 |
| device_username | 修改设备 OS username | 缺失保留；空串清除 |
| note | 修改设备自身备注 | 缺失保留；空串清除；不改地址簿条目备注 |
| strategy_name | 精确选择全局命名定义，持续关联该定义 | 缺失保留；空串写NULL解绑；非空名称缺失/歧义拒绝，不复制配置 |
| address_book_name | 在最终设备 owner 下精确唯一匹配既有命名簿，加入/更新设备条目 | 缺失不操作簿；空串、缺簿或重名拒绝，不自动建簿 |
| address_book_alias | 目标簿条目别名 | 缺失保留；空串清除 |
| address_book_note | 目标簿条目备注 | 缺失保留；空串清除，与设备 note 独立 |
| address_book_password | 目标簿条目 Password 原始字符串 | 缺失保留；空串清除；不写个人 Hash，不修改远端密码 |
| address_book_tag | 将一个完整标签名追加到目标簿条目，去重本次标签 | 缺失/空串不操作；不存在的定义以颜色0创建，不拆逗号 |

MySQL 的默认大小写/重音/尾空格折叠不用于匹配这些名称；请求不自动创建账户、组或地址簿，不清理其他簿。全部修改同一事务；提交前失败回滚，失败不会返回空成功。若COMMIT应答丢失，结果可能不明，不能仅凭失败响应断言数据库从未提交。相同赋值可重试；MySQL 同值更新的 changed-row 数为0不意味着目标不存在。

四个簿附属字段仅能与非空 `address_book_name` 同时提供。owner 为本次 `user_name` 指定的启用用户，否则沿用设备当前 owner；owner=0、不存在或禁用均拒绝。命名簿为 `collection_id>0` 的既有集合，不要求预先有共享授权，也不把个人簿 cid=0 当作具名集合。

只加入/更新目标 owner＋簿＋设备的条目，保留其他簿和个人条目，不写 `Peer.AbId/Alias`，不触发主簿预设回流。历史同范围重复行全部保留并窄更新，各行未指定字段独立保留。新条目快照本次最终设备 hostname/username 与 OS 平台；已有条目不刷新这些基础字段。非空 tag 追加需要严格读取原 tags，损坏 JSON 整次失败；空 tag 或只改附属文本不规范化无关历史标签。

共享密码沿用现有簿读取权限，不新增权限、哈希转换或密码日志。仅加入簿不会改变该簿既有授权。

命名定义及管理员CRUD由PRE02-C交付；PRE02-D新增设备可空外键及`strategy_name`消费。命名选择先锁设备再锁定义，验证严格配置；与本次归属/地址簿/资料修改同一事务，任一步失败全部回滚。重命名按稳定ID保留关联，定义修改下次心跳生效，引用中的定义拒绝删除。命名、默认、单设备与预设优先级见[命名策略](named-strategies.md)。

常见失败：会话无效401、普通用户403、参数/不存在或不匹配目标400、存储故障503、取消408、超时504。响应只含固定错误文本，不包含底层 SQL、token 或备注内容。

## PRE01-B 模型变更

PRE01-B数据库版本279，仅在已有设备行新增 `peers.note` 非空文本列、默认空串；行粒度仍是一台登记设备，row_id 主键不变。旧行回填空串，已有备注不覆盖；`AddressBook.Note` 继续是所属用户/地址簿/设备条目的独立事实，不新增备注表、历史或审计字段。

升级失败不记录279；SQLite/PostgreSQL 的 schema 和版本事务回滚，MySQL DDL 可能部分保留，重试会完成回填与约束。部署前仍需适用数据库升级/恢复流程，不把自动迁移测试当作生产备份恢复验收。

已有 GET `/api/peers` 的 note 字段投影设备备注，沿用当前授权范围与分页，未改用户内部备注或簿备注。

PRE02-D数据库版本281，仅在已有peers增加strategy_definition_id可空外键及非唯一索引，指向strategy_definitions.id；旧设备NULL、不推断关联。引用中RESTRICT删除，既有每设备策略保持独立，不增关系表/历史或配置副本。SQLite用单条nullable REFERENCES新增而不重建设备表，并修正旧Note默认值元数据导致的无意义重建，保留既有设备、受管历史、自定义触发器和索引。

## 验证边界

HTTP/core 测试涵盖管理员/会话拒绝、严格请求形状、五项字段、事务失败、实例隔离、过时 principal 重查、列表备注隔离及刷新。实库增量测试为 `internal/integration/client_assignment_test.go`：真实 COMMIT 失败回滚/重试、名称精确匹配、角色/撤销/期限重查、独立连接池竞争、279失败重试和数据库默认/非空约束。

地址簿分配新增 core/生产HTTP读写权限回归与 `internal/integration/client_assignment_addressbook_test.go` 实库验证：精确簿名、重复行窄更新、标签/密码回读、真实最后AB UPDATE后的COMMIT故障回滚重试，以及独立池双CLI追加与普通客户端标签重命名的竞争。集合更新/删除同时加入 owner升序→集合锁，逐SQL错误回滚，避免CLI分配和集合变更使用相反锁序。旧管理控制器的所有授权竞态、主簿引用删除政策未因此全部解决，不能把此协调描述为整个legacy管理面的授权改造。

本批尚未部署或执行真实官方 `--assign`。真实客户端的安装/root门槛、传参编码、空响应 Done、资料/设备备注/簿备注/原始共享密码及标签回读、命名绑定/更新/改名/解绑后的实际应用、失效管理员 token 错误，以及匿名重报和失败节流都需单列验收。CLI 写 hostname/username 后仍可能被后续基础 sysinfo 覆盖，因为 stock 已将本地预设折叠进这两个基础字段；不承诺永久管理优先。
