# 客户端审计写入

连接、文件事件先提交审计及收据事务，再返回 HTTP 200 空响应体。
依赖、绑定连接缺失、取消及提交失败均不返回成功 ACK；同 nonce 不同载荷
返回 409。无 nonce 请求保留 best-effort 行为。

`session_id` 从 JSON uint64 直接转换为十进制字符串存储，覆盖整个 u64 范围，
拒绝负数、小数和溢出。既有数据库字段已经是字符串；此前 float64 路径可能
造成的历史精度损失没有可推断修复来源。

版本 277 增加 `audit_delivery_receipts`，一行对应端点、设备 id/uuid、nonce
的摘要主键，另一列仅保存语义载荷摘要。业务写入与收据同事务，失败不占用
nonce。唯一键仲裁跨服务实例竞争；冲突事务结束后再读取已提交收据，避免
在 PostgreSQL 已中止事务中查询。同键同载荷 ACK 不重写业务数据。
不从旧记录推断收据，不设置任意到期时间；保留期间保证去重，删除收据会失去
对应保证。删除业务审计不自动删除收据，因此旧重试不会复活业务记录。

连接按受控设备 id/uuid/conn_id 隔离。认证和关闭在相同 session 或零 session
的存活候选中选择最新记录，防止崩溃遗留存活行抢占新连接；没有存活候选时
才检查历史同 session。已收录旧事件首先由收据识别。客户端协议没有连接代次
或事件发生时间，升级前或没有收据、从未见过的旧延迟事件仍有歧义；这里不
承诺业务事件的 exactly-once 时序。升级前在途请求也可能首次重复一次。

测试使用真实生产 HTTP 路由及 SQLite，覆盖空 ACK、u64 边界、事件关联、
崩溃重连、重试冲突、提交失败与可重投、独立数据库连接池的并发重复。
真实 Rust/Flutter 客户端、MySQL/PostgreSQL 运行和部署联调仍待验证。
新增告警、活动连接、审计备注与录制接口继续按后续阶段推进。
